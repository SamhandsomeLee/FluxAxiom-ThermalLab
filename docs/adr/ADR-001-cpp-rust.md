# ADR-001：C++ / Rust 分界

- 状态：草案
- 日期：2026-11-02
- 依据：执行方案 v1.0 §8.2；设计文档 V2.0 §0.2、§5、§5.1

## 背景

ThermalLab 要能在没有 FluxAxiom、没有 LLM 时完成测温、录像、推理和 Benchmark。Agent 又要能在以后发起实验。两边如果共用一种语言和同一套对象，Agent 的失败会进到设备与温度路径里。G0.8 要把这个边界写下来。这一阶段不实现 Agent。

## 决定

- C++ 拥有确定性执行：采集、解码、红外处理、GPU 资源、模型加载、推理、性能打点、设备读写、串口和 ESP32。
- Rust / FluxAxiom 只负责任务规划、工具选择、模型调用、预算、审批发起和审计。报告由它组织，事实计算仍在 C++。
- 两边只通过版本化 HTTP API 交换控制、结果、告警和实验元数据。帧不走这条 API。
- 实验队列与状态由 C++ 保存。Rust 调用并观察。`ExperimentJob` 与 FluxAxiom 的 `Run` / `Attempt` 只通过关联 ID 关联，`RunId` 不充当 `ExperimentId`。
- SDK、桌面、测温、录像、推理和 Benchmark 不链接 FluxAxiom，也不在进程内调用 LLM。
- 本仓库 G0 不加入 Rust 目标、Cargo 清单或 Agent 适配层。

## 备选与取舍

| 方案 | 代价 | 不采用的原因 |
| --- | --- | --- |
| 全部用 C++，Agent 也写在本仓库 | 少一种语言 | Agent 的规划和审批不是红外运行时的职责，失败时不应留在设备进程里 |
| 全部用 Rust | 要重写媒体、相机和 GPU 路径 | 设计文档 §5.1 把这些放在 C++，因为现有生态和数据布局在那边 |
| C++ 执行，Rust 只做 Agent | 两套构建，HTTP 边界要版本化 | 采用。核心产品可以在没有 Agent 时运行 |

## 证据

没有新的实测。依据是设计文档 §5 的职责句和 §5.1 的矩阵，以及 §0.2 第 1、5 条。G0 的代码只有 `tl_get_version`，没有 Rust 文件。Agent 调用待 G6 实测。

## 后果

- G6 之前不在本仓库实现 Tool Adapter 或 Effect。
- HTTP API 的路径版本在服务契约里冻结，不在这一份 ADR 里发明路径。
- 若以后要把推理或设备读写放进 Rust，先修订本 ADR，再改代码。
