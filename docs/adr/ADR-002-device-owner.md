# ADR-002：设备所有者与进程演进

- 状态：已采用
- 日期：2026-11-02
- 审阅：2026-11-02 由草案改为已采用
- 依据：执行方案 v1.0 §8.2；设计文档 V2.0 §0.2、§4.4

## 背景

相机、帧缓存和 GPU 上下文不能同时有两个写入者。桌面、服务、Web 和 Android 若各自打开设备，后打开的一方会抢走画面或把温度算在别人的帧上。G0 还没有设备代码，但后面的进程划分要先定下来。

## 决定

- 同一设备同一时刻只有一个所有者。帧缓存、GPU 上下文和推理执行跟这个所有者走。
- G0 没有设备，没有所有者。
- G1 的所有者是 SDK 示例进程。没有桌面。
- G2–G3 的所有者是桌面进程，SDK 内嵌在进程里。桌面经 `InProcFrameChannel` 取帧，经 `InProcClient` 调用。QML 和 ViewModel 不直接拥有设备。
- G3 的服务骨架只管理实验，不从桌面拿走预览设备。Benchmark 读数据集文件，不占相机。
- G4 起所有者改为 ThermalService。桌面改用 `RemoteClient` 和 `ShmFrameChannel`。Web 与 Android 只发控制请求。切换时 QML 页面和 ViewModel 不改。
- 高频帧不进数据库、durable event 或普通日志。

## 备选与取舍

| 方案 | 代价 | 不采用的原因 |
| --- | --- | --- |
| 从 G1 起就用独立服务占有设备 | G1 要先做服务、鉴权和共享内存 | G1 的验收是纯 C 回放，没有桌面和服务 |
| 桌面一直占有设备，不做服务 | 远程端无法成为同一套控制路径 | 设计文档 §4.4 把 G4 的所有者定为 ThermalService |
| 按 §4.4 分阶段移交 | G4 要改进程边界，并保持 QML 不改 | 采用 |

## 证据

没有设备实测。依据是设计文档 §4.4 的表。§0.2 第 2 条把 G1–G3 都写成桌面进程，比 §4.4 粗：§4.4 写明 G1 没有桌面。本草案采用 §4.4。G0.4 的 Jetson 运行仍是 `Blocked`，不在这里补设备日志。

## 后果

- G1 不创建 ThermalService，也不创建空的 `IFrameChannel` 实现。
- 规则文件里「G1–G3 是桌面进程」与 §4.4 不一致。与本草案同时改成 §4.4 的说法。
- 若 G3 的实验服务要提前独占相机，先修订本 ADR。
